# soundiya

> **Поддержать проект (по желанию):**
>
> - ETH: `0xBF7a72FF3637D979111243461BA236F608DE769a`
> - USDT (сеть TRON, TRC20): `TSiH6q687T3TGUrTfbUPWQsiD4Vc8Hq4NP`

SoundCloud для Яндекс Станций: говорите «Алиса, включи …», и музыка играет из
SoundCloud прямо на колонке. Один маленький бинарник на Rust (~2,7 МБ), без
телефона и без аккаунта, со **встроенным обходом блокировок** (аналог zapret),
который работает без root-трюков, iptables и сторонних программ.

Проект построен на основе [spotiya](https://github.com/klockky/spotiya): голосовой
слой, приглушение при разговоре с Алисой и работа с ALSA оттуда, а Spotify-часть
заменена на собственный клиент SoundCloud, декодер AAC/MP3 и обход DPI.

## Чем отличается от Spotify-версии

- **Нет Spotify Connect.** У SoundCloud нет протокола «играть на устройстве», поэтому
  колонка управляется **голосом** и командой `soundiya` (по SSH/ADB), а не из приложения.
- **Можно без аккаунта.** Поиск и воспроизведение работают анонимно. Вход нужен только для
  «включи избранное».
- **Нет подписки.** Нужны только колонка с root-доступом и интернет.

## Что понадобится

- Яндекс Станция **Мини** (YNDX-0004) или **Мини 2** с уже полученным root-доступом
  (так же, как для spotiya; получение root в проект не входит).
- `adb` на ПК и IP колонки в вашей сети.
- Для сборки из исходников: Windows с WSL (или Linux) и Rust. Если у вас уже собирался
  spotiya, всё нужное есть.

## Быстрая установка (одна команда)

Подключитесь к колонке по adb и откройте её оболочку:

```sh
adb connect IP_КОЛОНКИ:5555
adb -s IP_КОЛОНКИ:5555 shell
```

В оболочке колонки вставьте строку целиком, **вместе со скобками**, и нажмите Enter:

```sh
(set -e; B=https://github.com/ShadowBlade83/soundiya/releases/latest/download; d=$(mktemp -d /tmp/soundiya.XXXXXX); trap 'rm -rf "$d"' EXIT; cd "$d"; echo 'Downloading soundiya...'; for f in SHA256SUMS soundiya install.sh run.sh start.sh stop.sh S99soundiya; do LD_LIBRARY_PATH=/system/vendor/quasar/libs /system/vendor/quasar/maind --gst-launch "souphttpsrc location=$B/$f ssl-strict=true ssl-ca-file=/etc/ssl/certs/ca-certificates.crt iradio-mode=false timeout=30 retries=1 ! filesink location=$f" >log 2>&1; grep -Fq 'EOS: end of stream' log && ! grep -Fq 'ERROR from ' log && [ -s "$f" ] || { echo "Download failed: $f" >&2; exit 1; }; done; sha256sum -c SHA256SUMS && sh install.sh)
```

Команда скачивает последний релиз с GitHub штатным загрузчиком колонки (`curl` не нужен), сверяет
контрольные суммы и запускает установщик. Тем же способом ставятся обновления. Ставит в
`/data/opt/soundiya`, добавляет автозапуск и команду `soundiya`. Вход и настройки при обновлении
сохраняются.

Дальше всё делается в той же оболочке колонки, и каждую команду вы вводите сами:

```sh
soundiya check    # проверить доступ к SoundCloud
soundiya auto     # подобрать стратегию обхода блокировок (несколько минут)
soundiya login    # по желанию: вход в аккаунт для «включи избранное»
```

Потом скажите: «Алиса, включи Radiohead». Удалить: `/data/opt/soundiya/install.sh uninstall`
(с `--purge` вместе с входом и настройками).

## Установка из исходников

Если GitHub с колонки недоступен или хотите собрать сами:

### 1. Собрать

Дважды щёлкните **`build.bat`** (Windows + WSL). Он соберёт ARM-бинарник и положит готовый
пакет в `dist\soundiya-armv7\`. Первый раз перед этим один раз подготовьте тулчейн в WSL:

```sh
bash scripts/bootstrap-arm.sh
```

То же самое на Linux/WSL вручную:

```sh
bash scripts/build-arm.sh && bash scripts/package.sh
```

### 2. Поставить на колонку

```sh
adb connect IP_КОЛОНКИ:5555
adb -s IP_КОЛОНКИ:5555 push dist/soundiya-armv7 /tmp/soundiya
adb -s IP_КОЛОНКИ:5555 shell sh /tmp/soundiya/install.sh
```

Установщик (запускается от root на колонке):

- проверяет, что бинарник запускается, и что в `/data` есть место;
- кладёт всё в `/data/opt/soundiya`, добавляет автозапуск `/etc/init.d/S99soundiya` и
  команду `soundiya`; корневую файловую систему он открывает на запись только на момент
  установки и возвращает в read-only;
- **отключает автозапуск spotiya**, если он стоит, потому что обе программы борются за звук и
  за Алису (`sh install.sh uninstall` вернёт его; чтобы оставить оба, запустите
  `KEEP_SPOTIYA=1 sh install.sh`);
- запускает службу. Настройки и вход сохраняются при обновлении: достаточно повторить шаг 2.

### 3. Проверить

Зайдите на колонку (`adb shell`) и выполните:

```sh
soundiya check
```

Вы увидите, на каком шаге что-то не так:

```
bypass mode: Auto (proxy 127.0.0.1:35763)
1. SoundCloud web player + client id: ok
2. search: ok, 5 tracks, first: ...
3. stream URL: ok (HLS Aac)
4. download and decode: ok, 89088 frames at 44100 Hz
5. account: anonymous mode (run 'soundiya login' for your favorites)
```

Затем скажите: **«Алиса, включи Radiohead»**.

## Голосовые команды

| Скажите | Что произойдёт |
| --- | --- |
| «включи / поставь / запусти / сыграй / врубай *исполнитель или трек*» | поиск в SoundCloud, очередь из 25 треков |
| «хочу послушать…», «давай послушаем…», «найди песню…» | то же; вежливые слова («пожалуйста», «а можешь…») не мешают |
| «включи песню / трек / группу *…*» | то же, с уточнением |
| «включи плейлист *…*», «включи альбом *…*», «включи музыку для сна» | плейлист или альбом (сначала ваши, потом общий поиск; не нашёлся — ищет трек) |
| «включи похожее» | треки, похожие на текущий |
| «включи популярное», «включи новинки», «включи популярный рэп» | тренды SoundCloud, по жанрам — самые популярные треки жанра |
| «что сейчас играет», «как называется эта песня», «кто поёт» | Алиса своим голосом называет трек и исполнителя |
| «перемотай на 20 секунд вперёд», «назад на 10 секунд», «с начала» | перемотка внутри трека (числа цифрами и словами; без числа 30 секунд) |
| «поставь на повтор», «зациклить песню» / «выключи повтор» | бесконечный повтор текущего трека; «повтори эту песню» запускает её сначала |
| «стоп», «пауза», «хватит», «выключи музыку» | пауза |
| «продолжи», «сними с паузы», «включи музыку» | продолжить (или повторить последний запрос) |
| «дальше», «пропусти», «следующий трек» / «назад», «предыдущая песня» | переключение |
| «включи избранное», «включи мои лайки» | ваши лайки с SoundCloud *(нужен вход)* |

Ссылку на плейлист голосом не продиктовать, зато её можно запустить командой:
`soundiya play https://soundcloud.com/<пользователь>/sets/<название>`.

Если в фразе есть слово «Яндекс» («включи Сплин на Яндекс Музыке»), запрос получает Алиса
(нужна подписка Плюс): soundiya встаёт на паузу, а «пауза», «дальше» и верхняя кнопка
управляют Яндекс Музыкой, пока вы снова не попросите музыку без слова «Яндекс».

Верхняя кнопка Алисы, пока загружена музыка, ставит её на паузу и продолжает.
Ответы Алисы голосом можно выключить: `"speech": false` в `state/config.json`.

Ставить лайки голосом нельзя: защита SoundCloud (DataDome) отвечает на такие запросы
с колонки капчей. Лайкайте треки в приложении или на сайте, а колонка проиграет их по
команде «включи избранное».

Команды про свет, таймеры, громкость и т. п. Алиса обрабатывает сама. Пока играет
soundiya, голосовые команды перехватываются раньше Алисы, поэтому её «оформите подписку
Плюс» не звучит. Во время разговора с Алисой музыка плавно затихает и возвращается.

## Вход в аккаунт (по желанию)

Токены вида `eyJ…` действуют сутки, затем вход нужно повторить (`soundiya login`); без
входа музыка продолжает играть в анонимном режиме. Нужен только для «включи избранное». У SoundCloud нет открытой регистрации приложений,
поэтому вход идёт по токену вашей собственной сессии в браузере. Это один длинный набор
символов, который сайт сам отправляет в каждом запросе.

**Где его взять (Chrome, Edge, Яндекс Браузер):**

1. Откройте [soundcloud.com](https://soundcloud.com) и войдите в аккаунт.
2. Нажмите **F12** и откройте вкладку **Network** (Сеть). В поле фильтра напишите `api-v2`.
3. Обновите страницу (**F5**) и щёлкните любой запрос в списке. Лучше всего подходят `me`
   и `track_likes`.
4. Справа на вкладке **Headers** найдите раздел **Request Headers** и строку
   `authorization: OAuth …`. Если её нет, щёлкните другой запрос.
5. Скопируйте всё, что стоит **после слова `OAuth`**. Подойдёт любой вид: `2-123456-…-…`
   или длинный `eyJ…`. Проще ещё так: правый щелчок по запросу → *Copy → Copy as cURL*;
   вставлять можно и всю команду целиком.

**Как ввести на колонке** (лучше с терминалом: `adb shell -t`, тогда работает Ctrl-C):

```sh
soundiya login
```

Вставьте скопированное и нажмите Enter. Успех выглядит так: `signed in as <ваше имя>`.
Отменить ввод: пустая строка, `q`, `exit` или Ctrl-D.

- `did not accept the token`: SoundCloud не принял этот токен. Возьмите другой запрос
  (шаг 3) и повторите.
- `no SoundCloud token found`: вставлено не то. Токен начинается с `2-` или `eyJ`.

Проверка: `soundiya status` покажет `account: signed in`, а «Алиса, включи избранное»
запустит ваши лайки.

**Токен, который не нужно менять каждый день.** По сообщениям пользователей, токен вида
`2-…` живёт дольше суток (точный срок неизвестен; сайт сейчас выдаёт в браузере только
`eyJ…`). Один пользователь получил `2-…` через Android-приложение Murglar («desktop site
токен» в настройках после входа через сайт). Это закрытое стороннее приложение, мы его не
проверяли и не рекомендуем: решайте на свой риск и не вводите пароль там, где не доверяете.
Автоматическое обновление `eyJ…` по refresh-токену сайта (`oauth_refresh_token`) пока не
сделано: неизвестен запрос, который сайт для этого отправляет.

**Безопасность.** Токен даёт доступ к вашему аккаунту. Не отправляйте его другим людям и
не вставляйте в чаты, issue и скриншоты, в том числе целые cURL-команды: в них тоже
есть токен. Он хранится только на колонке: `/data/opt/soundiya/state/oauth-token`,
права 600. Выйти: `soundiya logout` (токен удаляется с колонки). Если токен куда-то
попал, выйдите из аккаунта на soundcloud.com и войдите снова: старый токен перестанет
работать, затем сделайте `soundiya login` с новым.

## Если SoundCloud заблокирован: обход и прокси

В России SoundCloud режется оборудованием провайдера (ТСПУ), и у разных провайдеров это работает
по-разному. Поэтому в soundiya две вещи: набор стратегий обхода, из которого можно выбрать подходящую (или
доверить выбор автодиагностике), и запасной путь через прокси.

### 1. Стратегии обхода (аналог ByeDPI и zapret, без отдельной программы)

Весь трафик к SoundCloud идёт через крошечный локальный прокси внутри процесса (`127.0.0.1`, только
петля). Он меняет первое TLS-сообщение (ClientHello) выбранной стратегией, чтобы DPI не увидел имя сайта,
а остальной обмен пропускает как есть. Он также резолвит DNS через DNS-over-HTTPS (1.1.1.1 и 8.8.8.8),
если DNS провайдера подменяет ответы.

**Все 22 стратегии [Flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube)**
перенесены как есть (параметры HTTPS-профиля каждого `.bat`: режимы `fake`, `multisplit`,
`multidisorder`, `fakedsplit`, `hostfakesplit`, `seqovl` и его паттерн, фейки `stun`/`stun2`/Google/Sferum/
4pda/Sochi, моды `rnd`/`dupsid`/`sni=`, fooling `ts`/`md5sig`/`badseq`, повторы):

| Имя | Файл Flowseal |
| --- | --- |
| `general` | `general.bat` |
| `alt`, `alt2` ... `alt13` | `general (ALT).bat`, `general (ALT2).bat` ... `general (ALT13).bat` |
| `exp` | `general (EXP).bat` |
| `fake-tls-auto`, `fake-tls-auto-alt`, `fake-tls-auto-alt2`, `fake-tls-auto-alt3` | `general (FAKE TLS AUTO ...).bat` |
| `simple-fake`, `simple-fake-alt`, `simple-fake-alt2` | `general (SIMPLE FAKE ...).bat` |

К ним добавлены собственные приёмы: `split`, `splitearly`, `tlsrec`, `both`, `oob`, `disorder`,
`ttlfake<N>` (подробнее: `soundiya strategies`). Имя можно писать как угодно: `alt11`, `ALT 11`,
`general (ALT11)`.

Выбор стратегии:

```sh
soundiya strategies            # список и текущая стратегия
soundiya strategy alt11        # выбрать (сразу и на будущее, перезапуск не нужен)
soundiya strategy auto         # вернуть автоматический выбор
soundiya strategy off          # без обхода
```

**Автодиагностика (`soundiya auto`).** Пробует каждую стратегию по очереди, каждую на отдельном
экземпляре прокси: страница soundcloud.com и её первый скрипт должны скачаться целиком. Для каждой видно
результат и причину (`stalled after 7505 bytes`, `no answer`, ...). Самая быстрая из прошедших
сохраняется в `config.json` и сразу включается в работающей службе:

```sh
soundiya auto            # проверить все, выбрать лучшую (до 30 с на каждую, всего несколько минут)
soundiya auto --first    # остановиться на первой подошедшей
```

Если ни одна не прошла, команда так и скажет и подскажет прокси (раздел ниже).

Конфигурация в `/data/opt/soundiya/state/config.json`:

```json
{
  "profile": "auto",
  "voice": true,
  "bypass": {
    "strategy": "auto",
    "doh": true,
    "domains": [],
    "upstream_proxy": null
  }
}
```

`strategy` может быть `auto`, `off` или именем из списка (старое имя поля `mode` тоже читается).
`auto` без запомненного результата гонит короткий список (`both`, `tlsrec`, `split`, `splitearly`, `alt11`,
`alt9`, `general`, `simple-fake`, без обхода) и запоминает выигравшую в `state/bypass-cache.json`;
одно имя означает ровно эту стратегию. `domains`: дополнительные домены для обхода (поддомены
входят автоматически; уже включены `soundcloud.com`, `sndcdn.com`, `soundcloud.cloud`).

**Чем это отличается от `winws` на Windows.** `winws` перехватывает пакеты ядра и заменяет их своими,
так что на проводе остаются только его сегменты. Здесь реальные данные отправляет само ядро, а
подделки (фейки, перекрытие `seqovl`, куски в обратном порядке) вставляются рядом через raw-сокет (нужен
root, он у колонки есть). Для сервера это равнозначно, для DPI близко, но не идентично; поэтому не любая
стратегия, работающая у вас на ПК, сработает так же на колонке, и `soundiya auto` нужен именно для проверки
на самой колонке. Режим `syndata` (данные в SYN, `alt5`) применить нельзя: SYN формирует ядро, эта часть
пропускается.

Фейк-файлы (`stun.bin`, `stun2.bin`, `tls_clienthello_*.bin` в `fakes/`) взяты из репозитория Flowseal
(лицензия MIT, происхождение zapret).

**Предел этого способа.** Он помогает, когда провайдер смотрит на имя сайта и не склеивает рукопожатие.
Но современное ТСПУ умеет распознавать сами приёмы: на одной из проверенных сетей оно пропускало
рукопожатие с поддельными пакетами, а потом **обрывало соединение после 7-23 КБ**. Если `soundiya auto`
показывает у всех стратегий `stalled after ... bytes` или `no answer`, встроенный обход здесь бессилен.
Посмотреть, где именно рвётся, можно командой `soundiya fetch https://soundcloud.com/`.

### 2. Прокси (работает всегда)

Если обход не справился, пропустите трафик SoundCloud через любой прокси в вашей сети или в интернете, у
которого SoundCloud открывается:

```json
"bypass": { "upstream_proxy": "192.168.1.10:7890" }
```

Поддерживаются:

| Запись | Протокол |
| --- | --- |
| `"192.168.1.10:7890"` или `"http://192.168.1.10:7890"` | HTTP CONNECT |
| `"socks5://192.168.1.10:1080"` | SOCKS5 без логина |

Через прокси приёмы не применяются: прокси получает обычный, не искажённый трафик, только для адресов
SoundCloud, остальной трафик колонки идёт как раньше. Что можно поднять в качестве прокси:

- на ПК или роутере, где SoundCloud работает (VPN-клиент или Clash/v2ray с включённым «разрешить
  подключения из LAN», обычно порт 7890/7891 или 1080);
- `ssh -D 0.0.0.0:1080 user@сервер` на любом ПК в сети, у которого есть доступ к VPS за границей;
- свой сервер с `tinyproxy`, `3proxy`, `dante`.

Чем отличается от VPN на роутере: здесь через прокси идёт только SoundCloud, а не весь трафик колонки.

## Команды `soundiya`

```
soundiya check               проверить SoundCloud и обход
soundiya strategies          список стратегий обхода и текущая
soundiya strategy <имя>      выбрать стратегию (alt11, general, auto, off, ...)
soundiya auto [--first]      автодиагностика: проверить все стратегии, выбрать лучшую
soundiya fetch <URL>         скачать адрес через обход и показать, где оборвалось
soundiya tone                сыграть тестовый звук на колонке
soundiya status              что играет сейчас
soundiya play <запрос>       найти и включить
soundiya play <ссылка>       ссылка soundcloud.com на трек, плейлист (в том числе закрытый) или артиста
soundiya playlist <название> плейлист или альбом по имени (сначала ваши, если вы вошли)
soundiya top | trending [жанр]  популярное; related: похожее на текущий трек; now: что играет
soundiya pause | resume | next | prev
soundiya fav                 включить лайки (нужен вход)
soundiya volume 0-100        громкость колонки
soundiya login | logout
```

Служба: `/data/opt/soundiya/start.sh`, `stop.sh`. Журнал: `/tmp/soundiya.log`
(лежит в RAM и усекается при превышении 1 МБ). При сбое служба перезапускается сама.

| Симптом | Что делать |
| --- | --- |
| `soundiya check` падает на шаге 1 или 2 | блокировка: `soundiya auto` (подбор стратегии), если не помогло, `upstream_proxy` |
| Шаг 3 говорит про формат потока | у трека нет AAC/MP3-потока (редкие треки); попробуйте другой |
| Шаг 4 зависает или падает | проблема с CDN `*.sndcdn.com`/`*.soundcloud.cloud`: то же, что выше |
| Играет, но тихо или без ответа Алисы | `soundiya volume 70`; в `/tmp/soundiya.log` ищите `voice:` |
| Алиса отвечает поверх команды | сообщите с фрагментом журнала; отмена ответа уже отправляется 3 раза |
| `soundiya is not running` | `/data/opt/soundiya/start.sh`, смотрите `/tmp/soundiya.log` |

## Обновление и удаление

**Обновить:** соберите заново и повторите шаг 2: вход и настройки сохраняются.

**Удалить** (пакет должен лежать в `/tmp/soundiya`, как в шаге 2):

```sh
adb shell sh /tmp/soundiya/install.sh uninstall            # вход и настройки сохраняются
adb shell sh /tmp/soundiya/install.sh uninstall --purge    # удалить всё, включая вход
```

Если вы отключали spotiya при установке, при удалении его автозапуск включится обратно.

## Разработка

```
src/
  main.rs         CLI и главный цикл (очередь, голосовые команды, статус)
  soundcloud.rs   клиент SoundCloud: client_id, поиск, потоки, избранное
  fmp4.rs         разбор fMP4/CMAF: кадры AAC из HLS-сегментов
  player.rs       загрузка, декодирование (symphonia), вывод в ALSA, пауза
  bypass.rs       локальный прокси: выбор стратегии, гонка, исполнение плана, DoH, upstream-прокси
  strategy.rs     22 стратегии Flowseal как данные и построение плана пакетов (чистая логика, с тестами)
  rawfake.rs      подделка TCP-сегментов своего соединения (ts/md5sig/badseq/badsum, seqovl) через raw-сокет
  diagnose.rs     автодиагностика: перебор стратегий и выбор лучшей
  fakes/          фейк-пейлоады из репозитория Flowseal
  voice.rs        события Алисы, распознавание команд, отмена её ответа
  control.rs      сокет управления для команды soundiya
  mixer.rs, ducking.rs, volume_guard.rs, audio_guard.rs   громкость и приглушение
packaging/        установщик и скрипты запуска
```

Тесты: `cargo test` (нужны `libasound2-dev` и `pkg-config`). Сборка под колонку:
`scripts/build-arm.sh` (тулчейн Linaro gcc 6.5, glibc ≤ 2.23, проверяется
`scripts/check-arm-abi.sh`).

## Важно знать

- Это **неофициальный** клиент: он пользуется теми же публичными адресами, что и веб-плеер
  SoundCloud. Правила и поведение сервиса могут меняться, и тогда понадобится обновление.
  Используйте для личного прослушивания и уважайте правила SoundCloud и права исполнителей.
- Воспроизводятся треки, доступные вашему аккаунту (или анонимно) в веб-плеере. Платный каталог
  и Go+ обходить проект не пытается.
- Проект не связан ни с SoundCloud, ни с Яндексом.
